# Guru Report — 13인 표결을 DB에 쌓는다

**산출물은 파일이 아니라 `guru_votes` 테이블의 행이다.** 종목 하나가 한 행이고, 13인의 판정이 13개 컬럼에 0~3 점수로 들어간다.

| 점수 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| 의견 | 매수 | 보유 | 관망 | 매도 |

숫자가 클수록 부정적이라 `order by g0` 하면 그대로 랭킹이 된다.

컬럼 번호는 종합 스크리너 프리셋 순서와 같다. `g0`은 거장이 아니라 13인의 파생 종합값(최빈값, 동률이면 보수적인 쪽).

| | | | | | |
|---|---|---|---|---|---|
| g1 벤저민 그레이엄 | g2 세스 클라먼 | g3 모니시 파브라이 | g4 조엘 그린블라트 | g5 앙드레 코스톨라니 | g6 잭 슈웨거 |
| g7 워런 버핏 | g8 필립 피셔 | g9 뉴욕주민 | g10 피터 린치 | g11 애스워스 다모다란 | g12 존 템플턴 |
| g13 마이클 버리 | | | | | |

> **thinking은 끈다.** 종목당 13인 병렬이라 세션 extended thinking이 켜져 있으면 사고 토큰이 13배가 된다(서브에이전트는 세션 thinking을 상속하며 개별 지정 불가). 시작 전에 끄고 진행한다.

## 비용 감각 (먼저 읽어라)

거장 1인 = 약 5k 토큰(Sonnet, 실측 필요). **종목 하나 = 약 6만 토큰, 유니버스 51종목 = 약 320만 토큰.**
사용자가 종목 수를 지정하지 않고 "전체 돌려"라고 하면, `seed` 결과 종목 수를 보여주고 **예상 토큰을 알린 뒤 확인을 받아라.** 몇 종목만 원하면 그 종목만 돌린다.

1단계(핵심 데이터)와 유니버스 추출은 전부 결정론적 스크립트라 **토큰이 0**이다. LLM을 쓰는 곳은 2단계 13인 판정뿐이다. 직접 curl 하거나 데이터를 서브에이전트에게 수집시키지 마라 — 그러면 종목당 2.8만 토큰이 다시 붙는다.

## 사전 확인

- `.env`에 `SUPABASE_URL` / `SUPABASE_SERVICE_KEY`가 있어야 한다. 없으면 사용자에게 알리고 중단.
- 테이블이 없다는 오류(`PGRST205`)가 나면 `scripts/guru-votes.sql`을 Supabase 대시보드 SQL Editor에 붙여 넣어 달라고 요청한다. 이 DDL은 스크립트로 실행할 수 없다.
- 날짜는 오늘 `YYYY-MM-DD`.

## 1단계 — 대상 종목을 행으로 깔기 (토큰 0)

```bash
node scripts/guru-db.mjs seed          # 오늘 날짜, 해외, 피셔만 5단계
```

종합 스크리너 프리셋 14종(공통 + 거장 13)을 해외장으로 조회하고, 피셔만 5단계로 조건을 강화한 뒤(0단계면 95종목이라 혼자 유니버스를 뒤덮는다) 중복을 제거해 `(날짜, 티커)` 행을 만든다. 점수 컬럼은 비운 채로 둔다.

stdout에 티커 목록이 한 줄로 나온다. 이걸 그대로 다음 단계에 쓴다.

사용자가 특정 종목만 원하면 이 단계를 건너뛰지 말고, `seed` 후 그중 원하는 티커만 2단계로 보낸다 (행이 있어야 점수를 쓸 수 있다).

## 2단계 — 핵심 데이터 (토큰 0)

```bash
node scripts/guru-core.mjs AAPL MSFT NVDA ... --out-dir .cache/guru/{날짜}
```

한 프로세스에서 전부 처리한다 — Yahoo crumb를 한 번만 받으므로 종목당 0.7초다. 51종목이 30초면 끝난다. **13인을 띄우기 전에 미리 전부 만들어 둬라.**

실패한 종목은 stderr에 나온다. 그 종목은 건너뛰고 나머지를 진행한다.

## 3단계 — 종목별 13인 판정 (여기만 토큰을 쓴다)

**한 종목씩** 처리한다. 종목 하나에 대해 거장별 전용 에이전트 13개를 **한 메시지에서 전부 병렬로** 띄운다.

거장마다 `subagent_type`이 따로 있고, **판정 기준·말투·인물별 특수 지시·응답 형식이 전부 그 정의 안에 들어 있다.** 그래서 **스폰 프롬프트는 세 줄이면 끝난다**:

```
티커: {티커}
날짜: {날짜}
핵심 데이터: {저장소 절대경로}/.cache/guru/{날짜}/{티커}.md
```

> 스폰 프롬프트에 인물 설명·판정 기준·데이터 내용을 **적지 마라.** 정의에 이미 있고, 13배로 불어나 메인 컨텍스트에 그대로 쌓인다.

| subagent_type | 거장 | | subagent_type | 거장 |
|---|---|---|---|---|
| `guru-vote-graham` | 벤저민 그레이엄 | | `guru-vote-fisher` | 필립 피셔 |
| `guru-vote-klarman` | 세스 클라먼 | | `guru-vote-nyresident` | 뉴욕주민 |
| `guru-vote-pabrai` | 모니시 파브라이 | | `guru-vote-lynch` | 피터 린치 |
| `guru-vote-greenblatt` | 조엘 그린블라트 | | `guru-vote-damodaran` | 애스워스 다모다란 |
| `guru-vote-kostolany` | 앙드레 코스톨라니 | | `guru-vote-templeton` | 존 템플턴 |
| `guru-vote-schwager` | 잭 슈웨거 | | `guru-vote-burry` | 마이클 버리 |
| `guru-vote-buffett` | 워런 버핏 | | | |

이 정의 13개는 손으로 고치지 마라 — 판정카드에서 생성된 것이라 다음에 재생성하면 덮어써진다. 기준을 바꾸려면 페르소나 → 카드 → 정의 순으로 다시 만든다("판정카드 재생성" 참조).

> **`guru-persona` / `guru-persona-quant` / `guru-data` / `guru-value-driver` / `guru-synthesis`를 쓰지 마라.** 전부 풀 모드 전용이고 인당 비용이 10배다.

## 4단계 — 점수를 행에 쓰기 (토큰 0)

13개 응답을 **그대로** 이어붙여 stdin으로 넘긴다. 재가공·윤문 금지.

```bash
node scripts/guru-db.mjs put {날짜} {티커} <<'EOF'
인물: 워런 버핏 | 의견: 보유 | 확신도: 7 | 근거: ...
인물: 필립 피셔 | 의견: 보유 | 확신도: 7 | 근거: ...
...
EOF
```

스크립트가 인물 → 컬럼, 의견 → 0~3 매핑과 종합(g0) 계산을 한다. **너는 점수로 변환하지 마라** — 매핑이 어긋나면 조용히 틀린 칸에 들어간다. 인물명은 에이전트가 답한 그대로 넘기면 된다(성만 맞으면 매칭된다).

한 종목이 끝나면 다음 종목으로 간다. 중간에 끊겨도 DB에 쓴 데까지는 남는다.

## 5단계 — 완료 보고

```bash
node scripts/guru-db.mjs show {날짜}     # 저장된 표
node scripts/guru-db.mjs todo {날짜}     # 아직 판정 안 된 티커
```

사용자에게: 처리한 종목 수 + 종합이 매수/보유로 나온 종목(있으면 그것부터) + 13인이 크게 갈린 종목 1~2개 + 실패해서 남은 티커. 표 전체를 그대로 붙여넣지 마라.

이어서 돌릴 때는 `todo`로 남은 티커만 뽑아 3단계부터 반복한다.

## 실패 처리

- 13인 중 일부가 실패하면 **그 종목을 통째로 버리지 말고** 성공한 인물만 `put` 한다. 나머지 칸은 NULL로 남고 `g0`은 성공한 인물들로만 계산된다.
- 같은 날 같은 티커를 다시 돌리면 그 행을 덮어쓴다.
- `seed`는 기존 행의 점수를 지우지 않는다(merge). 하루에 여러 번 돌려도 안전하다.

# 풀 모드 ("자세히", "풀 보고서"라고 명시했을 때만)

마크다운 개별 보고서 13개 + 종합 최종 보고서를 `docs/report/{날짜}/`에 만드는 기존 파이프라인. **종목당 110~160만 토큰, 10~20분.** 사용자가 표결 결과를 보고 특정 종목을 지목했을 때만 쓴다.

① `guru-data`(데이터 팩) + `guru-value-driver`(가치 드라이버) 병렬 → ② `guru-persona` 9인 / `guru-persona-quant` 4인 병렬로 개별 보고서 → ③ `guru-synthesis` 종합.

- 1단계: 스폰 프롬프트에 티커·날짜·저장경로(`docs/report/{날짜}/_data/{티커}.md`)·레시피(`references/data-sources.md`) 절대경로. **"표결 모드"라고 쓰지 마라**(그러면 축약 팩만 만든다).
- 2단계: 페르소나 파일은 `references/personas/{인물명}.md`(카드가 아니라 원본). 데이터 팩·가치 드라이버 경로도 함께 넘긴다. 공통 규칙·템플릿·요약블록 형식은 에이전트 정의에 있으니 반복하지 마라.
- 계량 4인 = 다모다란(DCF), 그린블라트(마법공식), 그레이엄(내재가치 공식), 슈웨거(손익비·사이징) → `guru-persona-quant`. 나머지 9인 → `guru-persona`.
- 13개 요약 블록을 `_data/{티커}_요약.md`로 저장한 뒤 3단계에 넘긴다. 저장 경로는 `guru-synthesis` 정의에 고정돼 있으니 스폰 프롬프트에 적지 마라.
- 풀 모드로 돌렸어도 **표결 점수는 DB에 따로 넣어라** — 요약 블록의 의견을 4단계 `put`에 그대로 넘기면 된다.

# 공통

## 판정카드 재생성

카드(`references/cards/*.md`)는 페르소나 원본에서 표결에 쓰는 3개 섹션(투자 철학 핵심 / 종목 평가 체크리스트 / 매수·매도 판단 기준)만 기계적으로 뽑은 것이다. LLM으로 재작성하지 말고 아래를 그대로 실행하라:

```bash
cd .claude/skills/guru-report/references
mkdir -p cards
for f in personas/*.md; do
  awk '/^## / { s=$0; p = (s ~ /투자 철학 핵심/ || s ~ /종목 평가 체크리스트/ || s ~ /매수\/매도 판단 기준/) }
      /^# / && !/^## / { print; next }
      p { print }' "$f" > "cards/$(basename "$f")"
done
```

카드를 다시 뽑았으면 **서브에이전트 정의도 반드시 다시 생성한다**(카드가 정의 안에 박혀 있다):

```bash
node scripts/guru-agents.mjs
```

## 페르소나 재생성

`docs/books/`에 책이 추가/변경되었을 때: 해당 책을 읽는 일반 에이전트를 띄워 기존 페르소나와 같은 형식(frontmatter: name/book/book_file, 섹션: 투자 철학 핵심/종목 평가 체크리스트/선호·회피 기업/매수·매도 판단 기준/리스크 관점/말투와 성격/대표 인용구)으로 `references/personas/`에 생성한다. 기존 파일 하나를 형식 예시로 함께 읽게 하라. 생성 후 **판정카드를 다시 뽑고**, 새 인물을 `scripts/guru-db.mjs`의 `GURU_COLUMNS`와 DDL에 추가해야 한다(컬럼 추가는 DB 마이그레이션이다 — 사용자에게 확인받아라).

## 주의사항

- 이 점수는 서적 기반 시뮬레이션이며 투자 자문이 아니다. 사용자에게 결과를 보고할 때 말미에 이 한 줄을 붙인다.
- 스크리너 조건 강화 규칙은 `scripts/guru-universe.mjs`와 `app/src/components/screener-data-table.tsx` 두 곳에 있다. 한쪽만 고치면 화면과 DB가 갈린다.
- 서브에이전트 정의(`.claude/agents/guru-*.md`)를 고치면 model/effort/도구 정책이 바뀐다. 품질이 부족하면 `effort`를 한 단계 올리고, 더 아끼려면 내린다.
