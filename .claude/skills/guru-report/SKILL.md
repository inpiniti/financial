# Guru Report — 13인의 거장 투자 보고서

티커 하나를 입력받아 13인의 거장이 각자 판정을 내린다. **모드가 두 개**다.

| | 표결 모드 (기본) | 풀 모드 |
|---|---|---|
| 언제 | 그냥 티커만 던졌을 때, "분석해줘", "표결", "몇 명이 매수야" | "풀 보고서", "자세히", "개별 보고서", "--풀" 이라고 명시했을 때 |
| 파이프라인 | ① 핵심 데이터(1개) → ② 13인 표결(병렬) → ③ 집계표 저장 | ① 데이터 팩 + 가치 드라이버 → ② 13인 개별 보고서 → ③ 종합 최종 보고서 |
| 산출물 | `_data/{티커}_표결.md` 1개 (~1KB) | 개별 13개 + 최종 1개 + 데이터 2개 |
| 비용 | 종목당 약 13만 토큰 / 2~3분 | 종목당 약 110~160만 토큰 / 10~20분 |

**어느 모드인지 모호하면 표결 모드로 간다.** 사용자가 표결 결과를 보고 "이건 자세히 보자"고 하면 그때 그 종목만 풀 모드로 다시 돌린다.

> **thinking은 끈다.** 13인 병렬이라 세션 extended thinking이 켜져 있으면 사고 토큰이 13배가 된다. 두 모드 모두 시작 전에 thinking을 끄고 진행한다(서브에이전트는 세션 thinking 상태를 상속하며 개별 지정이 불가능하다). 이 작업은 메인 루프도 깊은 사고가 필요 없다.

# 표결 모드 (기본)

## V-1. 핵심 데이터 (guru-data, 표결 모드)

`Agent`, `subagent_type: "guru-data"`. 스폰 프롬프트에 담을 것:
- **"표결 모드"라고 명시** (이 한 단어가 에이전트의 동작을 바꾼다 — 2KB 핵심 파일 1개만 만든다)
- 티커, 오늘 날짜
- 저장 경로: `docs/report/{날짜}/_data/{티커}_핵심.md`
- 레시피 파일 절대경로: `.claude/skills/guru-report/references/data-sources.md`

**가치 드라이버(`guru-value-driver`)는 표결 모드에서 띄우지 마라.** 표결 정확도 기여 대비 가장 비싼 단계다(에이전트 1개 + 13인이 각각 읽는 비용).

## V-2. 13인 표결 (guru-vote × 13, 한 메시지에서 전부 병렬)

`subagent_type: "guru-vote"` — model·effort·도구(Read만)·maxTurns·응답형식은 정의에 고정. **스폰 프롬프트는 인물별 차이만 4줄**로 짧게:

1. "너는 {인물명}이다." + 판정카드 절대경로 — `.claude/skills/guru-report/references/cards/{인물명}.md`
2. 핵심 데이터 절대경로 — `docs/report/{날짜}/_data/{티커}_핵심.md`
3. 티커, 날짜
4. (계량 4인만) 한 줄 지시 — 다모다란 "성장률·마진 가정이 현재 가격에 이미 반영됐는지만 역산해 판단", 그린블라트 "자본수익률과 이익수익률 두 축만 보고 판단", 그레이엄 "안전마진이 있는지만", 슈웨거 "손익비와 진입 타이밍만". **숫자 나열은 시키지 마라.**
5. (린치·코스톨라니처럼 특유 프레임이 있으면) 한 줄 — 린치 "6가지 유형 중 어디인지 먼저 분류", 코스톨라니 "달걀 모형 국면 판정"

13인 명단: `워런-버핏`, `필립-피셔`, `피터-린치`, `세스-클라먼`, `모니시-파브라이`, `존-템플턴`, `마이클-버리`, `앙드레-코스톨라니`, `뉴욕주민`, `애스워스-다모다란`, `조엘-그린블라트`, `벤저민-그레이엄`, `잭-슈웨거`

> **표결 모드에서는 `guru-persona` / `guru-persona-quant`를 쓰지 마라.** 그 둘은 보고서 파일을 쓰고 웹 조사를 하므로 인당 비용이 10배다.

## V-3. 집계 (메인 루프가 직접, 종합 에이전트 없음)

13개 한 줄 응답을 그대로 모아 `docs/report/{날짜}/_data/{티커}_표결.md`로 저장한다. 재가공·윤문 금지. 형식:

```markdown
# {티커} 13인 표결 — {날짜}
| 매수 | 보유 | 관망 | 매도 |
|---|---|---|---|
| n명 | n명 | n명 | n명 |

## 판정 원문
(13개 한 줄을 매수→보유→관망→매도 순으로 정렬해 그대로 나열)
```

**3단계 종합 에이전트(`guru-synthesis`)를 띄우지 마라.** 집계는 문자열 카운트라 판단이 필요 없다.

## V-4. 완료 보고

사용자에게: 표결 숫자(매수 n / 보유 n / 관망 n / 매도 n) + 평균 확신도 + 매수측·매도측 대표 근거 각 1줄 + 파일 경로. 그 이상 늘리지 마라.

## V-5. 여러 종목을 한 번에 요청받았을 때

종목별로 V-1→V-2를 순차 진행하되, **한 종목의 13인은 반드시 한 메시지 병렬**로 띄운다. 나중에 통합 보고서를 만들 때는 각 종목의 `_표결.md`(~1KB)만 읽으면 된다 — 최종보고서(12KB)를 읽지 마라.

# 풀 모드 ('자세히'라고 명시했을 때만)

아래는 전부 풀 모드 전용이다. 3단계 파이프라인:
**① 공용 데이터 팩 → ② 13인 개별 보고서 (병렬) → ③ 종합 최종 보고서**

## 토큰 절약 구조 (이 스킬의 핵심 설계)

메인 루프(세션 모델 = Opus)는 **오케스트레이터**다. 실제 작업(데이터 수집·13인 보고서·종합)은 전부 전용 서브에이전트에 위임하고, 메인은 라우팅·조립·완료보고만 한다. 각 단계 서브에이전트는 `.claude/agents/`에 정의돼 있고 **model·effort·tools·maxTurns가 프론트매터에 고정**돼 있으므로, 스폰할 때 모델을 지정할 필요가 없다.

| 단계 | subagent_type | 모델 | effort | 도구 | 비고 |
|---|---|---|---|---|---|
| **표결 V-2 (13인)** | `guru-vote` | sonnet | low | **Read만** | 파일 안 씀·웹 안 함·2턴 완결 → 인당 ~6k 토큰 |
| 1 데이터 수집 | `guru-data` | sonnet | medium | Bash·Web·Read·Write | curl·파싱을 메인 밖에서 → Opus 컨텍스트 청정 |
| 1-b 가치 드라이버 | `guru-value-driver` | sonnet | medium | Web·Read·Write | guru-data 완료 후 **병렬** 실행, 13인과도 병렬 |
| 2 정성 거장(9인) | `guru-persona` | sonnet | low | Read·Write | 외부조사 필요하면 가능 (VALUE_DRIVERS 파일도 읽음) |
| 2 계량 거장(4인) | `guru-persona-quant` | sonnet | medium | Read·Write | 외부조사 필요하면 가능 (VALUE_DRIVERS 파일도 읽음) |
| 3 종합 | `guru-synthesis` | 세션(opus) | medium | Read·Write | 판단만 Opus, VALUE_DRIVERS로 신규 섹션 구성 |

**비용 구조**: 인당 비용을 지배하는 것은 파일 크기가 아니라 **턴 수**다. 한 턴이 늘 때마다 그 시점 컨텍스트 전체가 재청구된다. 풀 모드 개별 보고서가 인당 5~6만 토큰인 이유는 '보고서 Write'가 턴을 2개 더 만들기 때문이고, 표결 모드가 인당 6k인 이유는 읽고 바로 답해 2턴에 끝나기 때문이다. **에이전트 수를 줄이는 것보다 턴을 줄이는 것이 훨씬 효과가 크다.**

**금융 MCP 없음**: 이 환경엔 Daloopa/kFinance 등 금융 MCP가 없다. **ToolSearch로 MCP를 찾지 마라**(불필요한 스키마 로딩으로 토큰만 샌다). 1단계는 곧장 무료 Yahoo/EDGAR 경로를 쓴다.

## 사전 확인

- `references/personas/` 폴더의 페르소나 파일 목록을 먼저 확인한다 (Glob: `references/personas/*.md`). 이 파일들이 13인의 거장 정의다. (표결 모드는 이 확인을 건너뛰고 곧장 `references/cards/`를 쓴다.) 개수가 `docs/books/`의 책 수와 다르면, 누락된 책에 대해 페르소나를 재생성한 뒤 진행한다 (아래 "페르소나 재생성" 참조).
- 날짜 폴더는 오늘 날짜 `YYYY-MM-DD` 형식. 모든 산출물 경로의 기준: `docs/report/{날짜}/`
- 티커가 모호하면(예: 종목명만 준 경우) 가장 유력한 티커로 해석해 진행하고, 데이터 팩 헤더에 해석 근거를 남긴다.

## 1단계 — 공용 데이터 팩 작성 (guru-data에 위임)

13인이 **동일한 사실관계** 위에서 판단해야 하고, 각 기업의 **가치를 움직이는 핵심 드라이버**도 함께 파악해야 하므로, 필요한 데이터를 여기서 전부 수집해 파일 두 개로 저장한다. **메인 루프가 직접 curl/파싱하지 말고 서브에이전트에 위임**한다(그래야 JSON 덤프가 Opus 컨텍스트를 오염시키지 않는다).

### 1-1. 데이터 팩 (guru-data)

- `Agent` 도구, `subagent_type: "guru-data"` (모델·effort는 정의에 고정 — 지정 불필요). 스폰 프롬프트에 넘길 것:
  - 티커, 오늘 날짜
  - 저장 경로: `docs/report/{날짜}/_data/{티커}.md`
  - 레시피 파일 절대경로: `.claude/skills/guru-report/references/data-sources.md` (에이전트가 읽어 그대로 따른다)
- 에이전트가 데이터 팩을 저장하고 간결한 확인(저장 경로 + 핵심 수치 몇 개 + "확인 불가" 항목)만 반환하면, 메인 루프는 팩 전문을 다시 읽지 말고 그 확인만 신뢰한다.
- 데이터 팩에 반드시 들어갈 항목·간결성 규칙은 `guru-data` 정의에 명시돼 있다. (기본·신규 필드 포함)

### 1-2. 가치 드라이버 분석 (guru-value-driver) — 병렬로 guru-data와 동시 실행

- `Agent` 도구, `subagent_type: "guru-value-driver"` (모델·effort는 정의에 고정). 스폰 프롬프트에 넘길 것:
  - 티커, 기업명, 오늘 날짜
  - 데이터 팩 경로: `docs/report/{날짜}/_data/{티커}.md` (참고용 — 에이전트가 이미 읽음)
  - 저장 경로: `docs/report/{날짜}/_data/{티커}_VALUE_DRIVERS.md`
- **목적**: "이 기업의 가치를 움직이는 핵심 KPI 3~5개"를 동적 발굴. 예: NVIDIA → CUDA 점유율·데이터센터 매출비중·Blackwell 출하량 / Apple → 아이폰 교체주기·서비스매출·중국판매량·생태계 락인
- WebSearch로 그 기업 특유의 동인을 조사 (업종 하드코딩 × ). 출력: 표 + 서사 3~4쪽.
- 13인이 이 파일을 읽고 각자 그 기업의 진짜 핵심을 알고 판단하므로, 최종 보고서의 "가치 움직이는 핵심 드라이버" 섹션 근거가 된다.

## 2단계 — 13인 개별 보고서 (병렬 서브에이전트)

페르소나 파일 하나당 에이전트 하나를 **한 메시지에서 전부 병렬로** 띄운다 (Agent 도구, 백그라운드). **모델·effort·도구·템플릿·요약블록 형식은 서브에이전트 정의에 이미 들어 있으므로, 스폰 프롬프트는 페르소나별 차이만 짧게 담는다** (프롬프트를 13배로 부풀리지 않기 위함).

### 2단계 공통 사항

13인 에이전트(정성 & 계량)는 **3개 파일을 읽음**:
1. 자신의 페르소나 파일
2. 데이터 팩 (`_data/{티커}.md`)
3. **가치 드라이버 파일** (`_data/{티커}_VALUE_DRIVERS.md`) — 신규 추가

VALUE_DRIVERS 파일이 없거나 조회 실패하면 "확인 불가"로 진행. 파일이 있으면 참고해 그 기업의 핵심 KPI를 자신의 판단에 반영한다(의무 × → 선택적 인용).

### subagent_type 라우팅

- **계량 방법론이 핵심인 4인 → `guru-persona-quant`** (effort medium):
  - `애스워스-다모다란` (DCF 시나리오별 주당가치 + 역산 DCF)
  - `조엘-그린블라트` (마법공식: 자본수익률 + 이익수익률 EBIT/EV)
  - `벤저민-그레이엄` (내재가치 공식 V=EPS×(8.5+2g), NCAV)
  - `잭-슈웨거` (진입·손절·목표·사이징·손익비 숫자로)
- **나머지 9인 → `guru-persona`** (effort low):
  - `워런-버핏`, `필립-피셔`, `피터-린치`, `세스-클라먼`, `모니시-파브라이`, `존-템플턴`, `마이클-버리`, `앙드레-코스톨라니`, `뉴욕주민`

### 스폰 프롬프트에 담을 것 (인물별로 이것만)

1. "너는 {인물명}이다." + 페르소나 파일 절대경로 (`references/personas/{인물명}.md`)
2. 데이터 팩 절대경로 (`docs/report/{날짜}/_data/{티커}.md`)
3. **가치 드라이버 파일 경로** (`docs/report/{날짜}/_data/{티커}_VALUE_DRIVERS.md`) — 신규 추가
4. 저장 경로: `docs/report/{날짜}/{인물명}/{티커}.md` (폴더는 에이전트가 생성)
5. 티커, 날짜
6. (계량 거장만) 수행할 계산 지시 — 위 라우팅 괄호 안의 방법론
7. (린치·코스톨라니처럼 특유 프레임이 있으면) 한 줄 지시 — 예: 린치 "6가지 분류 중 어디인지(경기순환주 여부) 명시", 코스톨라니 "달걀 모형 국면 판정"

> 공통 규칙(세 파일 읽기, 매수/보유/매도/관망+확신도로 마무리, 요약블록만 반환, 보고서 템플릿)은 **서브에이전트 정의에 이미 있으니 스폰 프롬프트에 반복하지 마라.**

### 요약 파일 취합

13개 에이전트가 반환한 요약 블록(형식은 정의에 명시됨)을 그대로 모아 `docs/report/{날짜}/_data/{티커}_요약.md` 한 파일로 저장한다 (재가공 금지, 인물 순서대로 이어붙이기만).

## 3단계 — 종합 최종 보고서 (guru-synthesis에 위임)

종합 에이전트 **1개**를 띄운다. `subagent_type: "guru-synthesis"` (model 미지정 = 세션 모델, effort는 정의에서 medium). 스폰 프롬프트에 담을 것:

1. 티커, 날짜
2. 필독 3개 경로: `_data/{티커}_요약.md` + `_data/{티커}.md` + **`_data/{티커}_VALUE_DRIVERS.md`** (신규)
3. (선택) 표결이 한쪽으로 크게 쏠렸으면 그 사실을 힌트로 — 예: "이번엔 매수 0명이니 강세론은 '기업의 질'을 인정한 논거로 구성하라"
4. (선택) VALUE_DRIVERS에서 핵심 드라이버 3~5개를 최종 보고서의 신규 섹션에 특화 기재하도록 지시

> **저장 경로는 스폰 프롬프트에 넣지 마라.** 최종 산출물 경로는 `guru-synthesis` 정의에 `docs/report/{날짜}/최종/{티커}_최종보고서.md`로 고정돼 있다. 프롬프트에 다른 경로(예: `.../최종/{티커}.md`)를 적으면 에이전트가 정의 대신 그것을 따라 파일명이 틀어진다.
> 최종 보고서 형식·선택정독 규칙(최대 4개)·필수 진입가격대 표·면책 문구도 **guru-synthesis 정의에 이미 있다.**

## 완료 보고

모든 파일 생성 후 사용자에게: 종합 의견 + 표결 결과 + 13인이 가장 크게 갈린 쟁점 1~2개 + 생성된 폴더 경로를 요약해준다.

# 공통 (두 모드 모두)

## 페르소나 재생성

`docs/books/`에 책이 추가/변경되었을 때: 해당 책을 읽는 에이전트를 띄워(`subagent_type: "guru-persona"`가 아니라 일반 에이전트로) 기존 페르소나 파일과 같은 형식(frontmatter: name/book/book_file, 섹션: 투자 철학 핵심/종목 평가 체크리스트/선호·회피 기업/매수·매도 판단 기준/리스크 관점/말투와 성격/대표 인용구)으로 `references/personas/`에 생성한다. 기존 파일 하나를 형식 예시로 함께 읽게 하라. 새 인물이 계량 방법론 중심이면 위 2단계 라우팅의 quant 목록에 추가한다.

**페르소나를 추가/수정했으면 판정카드도 다시 뽑아야 한다.** 카드는 페르소나에서 표결에 쓰는 3개 섹션(투자 철학 핵심 / 종목 평가 체크리스트 / 매수·매도 판단 기준)만 기계적으로 추출한 것이다. LLM으로 재작성하지 말고 아래를 그대로 실행하라:

```bash
cd .claude/skills/guru-report/references
mkdir -p cards
for f in personas/*.md; do
  awk '/^## / { s=$0; p = (s ~ /투자 철학 핵심/ || s ~ /종목 평가 체크리스트/ || s ~ /매수/매도 판단 기준/) }
      /^# / && !/^## / { print; next }
      p { print }' "$f" > "cards/$(basename "$f")"
done
```

## 주의사항

- 이 결과물은 투자 참고 자료다. 풀 모드 최종보고서 말미의 "본 보고서는 서적 기반 시뮬레이션이며 투자 자문이 아닙니다" 문구는 guru-synthesis가 넣는다. **표결 모드에서는 완료 보고 말미에 메인 루프가 이 한 줄을 직접 붙인다.**
- 13개 에이전트 중 일부가 실패하면 실패한 것만 재시도한다. 그래도 실패하면 **표결 모드는 분모를 줄여서(예: 12인 중) 집계**하고 누락 인물을 명시한다. 풀 모드는 완성된 보고서·요약만으로 종합하되 누락을 알린다.
- 같은 날 같은 티커를 다시 돌리면 기존 파일을 덮어쓴다 (버전 관리가 필요하면 사용자에게 확인).
- 서브에이전트 정의(`.claude/agents/guru-*.md`)를 수정하면 model/effort/도구 정책이 바뀐다. 품질이 부족하면 해당 단계의 `effort`를 한 단계 올리고, 더 아끼려면 내린다.
